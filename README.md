# zfl-42 小型漆线雕工坊管理

独立静态前端应用，直接打开 `index.html` 即可使用（无需构建）。

## 交付包装与签收闭环

- 作品进入「待交付」后可**建立包装清单**（至少一项包装内容），状态变为「待签收」。
- 每件作品同一时刻**只能有一份未结束包装清单**：已存在时拒绝再建。
- 包装后调整**胎体材质、纹样主题、线条粗细、缺陷、阴干日期**任一项，清单**立即失效**（标记 voided 并记录原因与时间），作品**退回待交付**，历史清单保留，可重新包装。修改备注、金粉、计划交付日期等不影响清单。
- 签收必须填写**收货人、实际交付日期、签收号**三项，缺项直接拒绝；签收号在全工坊范围内唯一（返工后再签收也不能复用旧号）。签收后状态为「已签收」。
- 已签收作品不能直接改资料；如需补做，使用「补做修复」**只追加返工记录**，原签收记录与缺陷历史完整保留。返工完成回到「待交付」，可重新包装并再次签收（新单号）。
- 缺陷全程**只追加不改写**（defectHistory），返工中追加的缺陷会挂到对应返工轮次。

## 三层分离

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 规则层 | `js/rules.js` | 纯函数，无 DOM / localStorage；所有命令返回 `{ ok, error, works }` 且不可变更新，可直接在 Node 中测试 |
| 持久化层 | `js/store.js` | 只做 JSON 读写，支持注入内存 storage |
| 界面层 | `js/app.js` | 仅负责交互与渲染；每个动作都走规则层命令，成功后统一「改内存 → 持久化 → 重绘」 |

列表（今日待阴干、缺陷作品、最近签收）、风险统计（未结束包装、已失效清单、返工中、到期未签收等）全部由规则层的选择器派生，因此看板、统计与刷新后的 localStorage 状态口径一致。

## 其他功能

- 新增作品并记录胎体、纹样、线条、进度、阴干日期、金粉状态、缺陷、交付日期。
- 工序看板：贴线中 / 待阴干 / 上金粉 / 待交付 / 待签收 / 已签收 / 返工中。
- 主题筛选、状态筛选、按交付/阴干日期排序、JSON 导出。
- 旧版本数据（defect 字符串、logs）打开时自动迁移。

## 测试

```bash
npm install   # 仅测试需要 jsdom
npm test      # node --test
```

- `test/rules.test.js`：包装唯一性、清单失效、签收校验、签收号唯一、返工追加与再签收、统计口径、数据迁移、不可变性。
- `test/store.test.js`：持久化往返一致、损坏 JSON 容错。
- `test/dom.test.js`：jsdom 端到端，覆盖完整闭环、刷新后状态一致与界面统计同步。
